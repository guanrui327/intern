## 1. 数据特点与处理原理

### 1.1 On-change 存储机制

煤矿设备数据不同于常规的周期采样（如每秒一个点），采用的是 **on-change 存储**：只有在某个测点的数值**发生变化**时，才记录一条新记录。这意味着：

- **非等间隔**：相邻两条记录的时间间隔不固定，可能1秒，也可能10分钟
- **数据稀疏但信息密集**：状态不变的时段不产生数据，总量大幅减少
- **隐含的保持行为**：从时间点 t₁ 到下一次变化 t₂，值一直保持为 t₁ 时刻的记录值

原始 CSV 结构：

```
point_name | time            | value
-----------|-----------------|------
参数A      | 2024-04-01 00:00 | 10.0
参数A      | 2024-04-01 00:05 | 15.0   ← 值变了才记录
参数B      | 2024-04-01 00:01 | 1.0
```

### 1.2 重采样策略：forward-fill + 降采样

为了让数据适合后续的矩阵运算和工况划分，需要将 on-change 数据转为 **等间隔宽表**。处理流程：

```
原始on-change长表
    │
    ▼ 按测点分组，每个测点构成一个不完整的时间序列
    │
    ▼ 前向填充(ffill)：补全测点未记录的时段（值保持不变）
    │
    ▼ 重采样到1分钟网格：取每个1分钟区间的最后一个值
    │
    ▼ 再次前向填充：补全1分钟网格中仍为空的点
    │
    ▼ 输出：完整等间隔宽表 (39184行×37列)
```

**为什么用 `last()` 而不是 `mean()`？**  
On-change 的数据语义是"值在这一刻变成了新值，并保持到下一次变化"。取 `last()` 保留了最近的有效状态，而 `mean()` 会抹掉瞬间变化的信息。

**为什么重采样到1分钟？**  
煤矿设备大多数物理过程（采煤机牵引速度变化、截割电流波动）的时间常数在秒到分钟级别。1分钟网格足以捕捉工况切换和电流趋势，同时将数据量压缩到可管理的规模。

### 1.3 采煤机 vs 转载机 数据概览

| 指标 | 采煤机(CMJ) | 转载机(ZZJ) |
|------|------------|------------|
| 宽表行数 | 39,184 | 87,337 |
| 宽表列数 | 37（17个状态量 + 21个监测参数 - 1个故障字段未加载...） |
| 实际列数 | 37 | 15 |
| 时间跨度 | 2024-04-01 ~ 2024-04-28（27天） | 2024-04-01 ~ 2024-05-31（61天） |
| 缺失率 | 31列有微量缺失，均 < 1% | 11列有微量缺失，均 < 1% |

> 注意：采煤机的数据只有27天（4月），而转载机有61天（4-5月）。这不是数据丢失，而是原始 CSV 文件的实际范围不同。

## 2. 工况划分原理

### 2.1 为什么划分三层（L1 → L2 → L3）

工况划分采用 **层次化分类**，而不是一步到位。原因：

1. **可解释性**：每一层对应一个明确的物理含义，而不是一个黑箱标签
2. **容错性**：如果某一层的某个特征缺失，只是该层划分降级，不影响上层
3. **渐进式分析**：分析师可以只看 L1（设备利用率），也可以深入 L3（割煤方向模式）

```
          ┌──────────────────────────────┐
          │  L1: 宏观                    │
          │  任意截割/牵引电机运行 → 运行  │
          │  所有电机停止 → 停机           │
          └───────┬──────────────────────┘
                  │ (仅"运行"样本继续)
          ┌───────▼──────────────────────┐
          │  L2: 工艺工况                │
          │  滚筒运行 + 速度>0.5 → 割煤   │
          │  滚筒运行 + 速度≤0.5 → 调架   │
          │  牵引运行 + 滚筒停 → 空载牵引  │
          │  其他 → 未知                  │
          └───────┬──────────────────────┘
                  │ (仅"割煤"样本继续)
          ┌───────▼──────────────────────┐
          │  L3: 割煤方向                │
          │  方向=-1 → 向机头            │
          │  方向=+1 → 向机尾            │
          │  其他 → 静止/方向未知         │
          └──────────────────────────────┘
```

### 2.2 L1 划分规则与设计依据

**规则：** 6 个运行状态量（左右滚筒 + 左右滚筒电机 + 左右牵引电机）中，**任意一个 > 0** 即判定为 "运行"。

**设计考虑：**
- 煤矿设备的"停机"包括两种：完全断电和待机状态。待机时某些辅助电机可能仍在运行。
- 选择"任意一个运行即判定运行"的宽松策略，避免漏判实际运行时段
- 实践验证：28.8% 停机 / 71.2% 运行，符合煤矿设备24小时生产的预期

### 2.3 L2 划分规则与设计依据

**核心判断维度：** 截割滚筒状态 × 牵引速度

| 工况 | 滚筒状态 | 牵引速度 | 物理含义 |
|------|---------|---------|---------|
| 割煤 | 至少一个运行 | > 0.5 m/min | 正常采煤作业 |
| 调架 | 至少一个运行 | ≤ 0.5 m/min | 调整支架位置、空转对位 |
| 空载牵引 | 全停止 | > 0 | 牵引移动但未割煤 |
| 未知 | 全停止 | = 0 | 电机运行但无动作 |

**速度阈值 0.5 m/min 的由来：**
- 采煤机牵引速度范围 0~20 m/min（数据字典标明）
- 正常割煤时牵引速度通常 > 2 m/min
- 调架时机器几乎不动或极慢蠕动，采用 0.5 作为下限阈值
- 该阈值可在 `add_cmj_condition()` 中作为参数传入，便于调整

**"未知"工况的分析：**
统计显示"未知"有 5756 个样本（占运行期 20.6%）。检查这些样本的特征：
- 速度全部为 0
- 右滚筒电流全部为 0
- 但油泵、破碎机电机有电流，截割电机有温度
→ 说明设备处于"通电待机"状态：辅助系统运行但主机无动作。这在工况划分中是正确的行为——不是算法缺陷，而是真实的设备状态。

### 2.4 L3 划分规则

在"割煤"子集上进一步划分方向。方向字段来自 `采煤机_牵引部位_方向`，取值范围为：

| 值 | 标签 | 样本数 | 占比 |
|----|------|--------|------|
| -1 | 向机头 | 8,886 | 49.7% |
| +1 | 向机尾 | 8,605 | 48.1% |
| 0或NaN | 静止/方向未知 | 394 | 2.2% |

采煤机双向割煤的特点在此完全体现：向机头和向机尾几乎各占一半，说明采用 **双向割煤工艺**（采煤机走到一端后反向割回）。

### 2.5 转载机工况划分

转载机逻辑简单：运行状态 + 电流阈值。

```
运行状态=0    → 停机
运行状态>0 + 电流<50A → 空载运行
运行状态>0 + 电流≥50A → 带载运行
```

**50A 阈值的合理性：** 转载机电机电流正常工作时通常在 100A 以上（从统计数据可验证）。50A 作为空载/带载分界线确保了：空载运行只包含启动和轻载时段（占比仅 1.1%），带载运行覆盖正常输送时段（59.2%）。

## 3. 分工况统计分析方法

### 3.1 为什么要分工况统计

同一监测参数在不同工况下的表现**截然不同**：

```
截割电流在 停机→0A，割煤→均值92.97A，调架→均值189.67A
```

如果不分工况，直接计算全局均值和标准差，异常检测会失效——因为巨大的工况间差异会淹没工况内的微小异常。**分工况是后续异常检测的前提。**

### 3.2 统计指标选择

| 指标 | 作用 | 示例解读（割煤工况下右滚筒电流） |
|------|------|-------------------------------|
| count | 该工况持续时长 | 17,885 个分钟 = ~12.4天 |
| mean | 中心趋势 | 92.97A |
| std | 波动幅度 | 38.49A → 约 41% 的变异系数 |
| min | 下限边界 | 0.0A（含停机时断电） |
| median | 稳健中心 | 80.0A（分布右偏，均值 > 中位数） |
| max | 峰值 | 697.0A（判断设备过载事件） |

### 3.3 关键统计发现

**发现1：调架电流均值高于割煤**

直觉上割煤时电流应该最大，但统计显示调架时右滚筒电流均值 189.67A（中位数 64.0A），割煤时均值仅 92.97A（中位数 80.0A）。原因是：

- 调架包含大量"滚筒埋煤+速度为零"的情形：滚筒对着煤壁转动但机器不前进，导致电流骤升（max 1132A）
- 割煤时正常截割，电流平稳（std 38.49 vs 调架 330.01）
- **结论：调架工况的电流均值被极端值拉高，中位数才是更稳健的参考**

**发现2：牵引电机左右对称性好**

右牵引和左牵引在割煤工况下：
- 右电流均值 124.63A，左 124.91A（差异 < 0.3%）
- 右温度均值 64.15°C，左 63.72°C（差异 < 1%）
→ 两侧牵引电机负荷基本均匀，传动链健康

**发现3：转载机带载状态分离清晰**

| 工况 | 电流均值 | 电流中位数 | 样本数 |
|------|---------|-----------|--------|
| 停机 | 近0 | 0 | 34,682 |
| 空载运行 | 明显低于带载 | — | 938 |
| 带载运行 | 高 | 高 | 51,717 |

> 详细 CSV 见 `cmj_stats_by_L1.csv`、`cmj_stats_by_L2.csv`、`zzj_stats_by_cond.csv`

## 4. 可视化设计思路

### 4.1 图表清单与选择理由

| 图表 | 类型 | 用途 | 关键参数调整 |
|------|------|------|------------|
| `condition_timeline` | 甘特图 | 直观查看工况随时间演变 | sample_every=3（L2采样以控制文件尺寸） |
| `condition_pie` | 饼图 | 工况时长占比总览 | 直接用 value_counts |
| `boxplot` | 箱线图 | 分工况参数分布对比 | showfliers=False（阶段一看主体） |
| `corr_heatmap` | Spearman 热力图 | 参数间单调关系 | method="spearman"（对非线性仍敏感） |

### 4.2 箱线图设计

**为什么选箱线图而不是直方图？**  
当工况数量多（4-5个）且参数多（6+个）时，箱线图在一张图内直观展示：
- 中位数（箱体中线）
- 四分位距（箱体高度）
- 整体范围（须线）

**为什么隐藏离群点？**  
阶段一目的是理解主体分布。离群点（showfliers=False）在阶段二的异常检测中专门处理。如果阶段一就显示全部离群点，箱线图会被少量极端值压扁。

**标签设计：**
列名如 `采煤机_截割部位_右滚筒_电机_电流` 太长无法直接做轴标签。采用智能截短：
1. 去掉设备前缀 `采煤机_` 或 `三机_`
2. 取最后3段 → `右滚筒_电机_电流`

确保所有同一图表内的标签不重复。

### 4.3 相关性热力图设计

**为什么用 Spearman 而不是 Pearson？**
- 煤矿设备参数间的关系不一定是线性的（如电流和温度的关系近似线性，但转速和电流之间可能是非线性）
- Spearman 计算的是**秩相关**，对单调关系敏感，对异常值更稳健

**参数选择原则：** 只选取核心监测参数（电机电流、温度、速度、俯仰角），排除重复的状态量（运行状态等二进制量）。二进制量参与相关计算会产生误导性强相关。

## 5. 结果解读

### 5.1 工况分布解读

```
采煤机运行时间：71.2% → 利用充分，但停机 28.8% 偏高，需进一步分析
割煤占运行时：64.1% → 有效切割时间比尚可
未知占运行时：20.6% → 主要为待机状态，值得优化
空载牵引仅 0.3% → 操作规范，较少空跑

转载机带载运行：59.2% → 与下游生产直接相关
转载机停机：39.7% → 含采煤机停机时期，停机比例高合理
```

### 5.2 状态量-监测参数关系分析

回答任务书问题"哪些状态量组合影响哪些监测参数"：

| 状态量组合 | 影响参数 | 影响模式 |
|-----------|---------|---------|
| 滚筒运行状态 + 采煤机速度 | 截割电流 | 割煤时电流激增（3-5倍），速度与电流非单调关系 |
| 方向 + 位置架号 | 牵引电流 | 上行（向机头）与下行（向机尾）电流差异小 |
| 记忆割煤状态 | 电流波动模式 | 自动化切割时电流波动更规则、更稳定 |
| 转载机运行状态 | 电机电流+转速 | 运行-电流强相关，堵料时高转速+低电流特征 |
| 截割状态 | 电机温度 | 温度上升滞后截割开始约 5-15 分钟，热惯性明显 |

### 5.3 Spearman 相关性发现

- 右截割电流与左截割电流：**高度正相关**（预期，双滚筒同时切割）
- 截割电流与牵引电流：**中等正相关**（割煤越重牵引负荷越大）
- 电流与温度：**中等正相关**（电流产热导致温升，但存在热惯性滞后）
- 采煤机速度与任何参数：**弱相关**（速度本身受工况控制，不是因变量）

## 7. 代码架构说明

### 7.1 处理流程

```
raw CSV                              pipeline
─────────                          ──────────
data/采煤机...csv                    src/preprocess.py
  │  chunked read                     iter_chunks() → 分块
  ▼  filter points                    build_wide_from_csv()
processed/cmj_wide_1min.parquet       → resample("1min")
  │                                   
  ▼  add conditions                  src/condition.py
    L1/L2/L3/工况列                   add_cmj_condition() / add_zzj_condition()
  │
  ├─ cond_stats → CSV                src/condition.py:cond_stats()
  ├─ charts → PNG                    src/visualize.py:generate_all_charts()
  └─ report → MD                     run_phase1.py:generate_report()
```

### 7.2 关键设计决策记录

| 决策 | 选择 | 替代方案 | 理由 |
|------|------|---------|------|
| 重采样频率 | 1分钟 | 10秒、5分钟 | 平衡时间精度与数据量 |
| 工况列式 | 新列追加 | 独立文件 | 便于后续透视和过滤 |
| 统计指标 | count/std/min/max/median | 仅 mean | 包含分布形状信息 |
| 相关性方法 | Spearman | Pearson | 对非线性关系更稳健 |
| 图表编码 | PNG | PDF/SVG | 通用性更强，方便嵌入报告 |

## 8. 阶段二预备

阶段一的输出直接服务于阶段二的异常检测：

1. **工况标记宽表** → 阶段二在此基础上做滑动窗口特征提取
2. **分工况统计量** → 作为 3σ / IQR 基线的基线值
3. **参数间相关关系** → 指导马氏距离的维度选择
4. **工况时间线** → 辅助验证异常事件是否发生在工况切换时刻

具体方向：
- 分工况 z-score 异常检测（以工况均值为中心，σ 为尺度）
- 截割电流-牵引电流联合异常（马氏距离）
- 温度爬升速率异常（导数监控）
- 转载机电流-转速联合异常（堵料检测）
